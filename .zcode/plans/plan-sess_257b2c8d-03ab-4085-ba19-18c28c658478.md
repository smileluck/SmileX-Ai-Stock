# 财报分析列表增强 + 分析策略配置化

## 先回答第 2 问：目前分析策略在哪里改

财报解读的 system prompt **硬编码**在 `backend/modules/financial/services/financial_service.py` 的 `_FINANCIAL_SYSTEM_PROMPT`（约 L36-62），目前只能改代码；所用模型由「LLM配置」页「趋势预测」场景绑定决定（复用 `sys_ai_model_binding` 的 trend_prediction）。大盘/板块/资讯分析有页面可配的「分析策略」抽屉（`BusinessAnalysisConfig`），财报模块没有——本次按同一模式补齐配置化。

## 一、股票名称修复（数据根因：新浪接口"股票名称"列为空 → report 表 NULL → 解读记录继承 NULL）

1. `financial_fetcher.fetch_financial_reports`：名称为空时用 `modules/stock/services/_sina.py` 的 `fetch_spot_quotes([_to_sina_code(code)])` 批量兜底（照抄 `stock_hot_fetcher._fill_quotes` 模式）
2. `sync_reports`：upsert 时对已有行 stock_name 为空的一并回填
3. 迁移 0028（DB 内回填，快）：`business_financial_report.stock_name`、`business_financial_interpretation.stock_name` 从 `business_research_report`（stock_name 非空按 code 取最新）回填
4. 前端列渲染已有 `{code} - name`，照研报中心样式优化名称展示

## 二、所属行业（全库无股票主数据表，来源链：研报表 → 东财个股信息）

1. 迁移 0028：`business_financial_interpretation` 加 `industry String(50) nullable`；存量从 `business_research_report.industry` 按 code 取最新回填
2. `submit_interpretation` 创建记录时填 industry：查 research_report 最新 industry → 兜底 `ak.stock_individual_info_em`（to_thread，失败 None）；stock_name 同步走 sina quotes 兜底
3. `FinancialInterpretItem` schema 加 `industry`；前端列表加「行业」列（照研报中心 industryCol 模式），抽屉头部显示
4. 实现阶段：对 research 未覆盖的存量股跑一次性 akshare 回填脚本

## 三、下期盈利增长预测的来源分析（两者都要）

**A. AI 预测驱动因素**：
- prompt 的 forecast 对象加 `"drivers": ["依据1","依据2"]`（2-4 条：产品量价/产能投放/成本变化/并购并表/基数效应等）
- typings `forecast.drivers?: string[]`；顶部解读卡与抽屉在 forecast 项内展示 drivers 小列表；列表「下期预测」列 hover 弹 NPopover（AI 依据 + 券商预测对照）；旧记录无该字段全部 `?.` 兼容

**B. 券商盈利预测对照**（数据源：`business_research_report` 的 rating/org_name/forecast{年份:{eps,pe}}/published_date）：
- 列表接口对本页 records 的 code 集合用 PostgreSQL `DISTINCT ON (stock_code) ORDER BY published_date DESC` 查每股最新一条研报，组装 `research_brief: {org_name, rating, published_date, forecast}` 附加到每行（schema 加可选字段，endpoint 手动组装）
- 展示在「下期预测」列 popover 与抽屉：如「中信证券 买入 · 2026EPS 3.2 / PE 18」

## 四、分析策略配置化（仿 analysis 模块 BusinessAnalysisConfig 模式）

1. 迁移 0028：建单行配置表 `business_financial_config`（id、prompt_template Text nullable、updated_at）
2. Service：`get_config` / `update_config`（upsert）
3. Endpoint：`GET/PUT /admin/financial/config`，权限复用 financial:list / financial:run（不新增菜单按钮）
4. `_interpret` user prompt 尾部追加「分析策略要求（用户定制，生成时必须遵循）：\n{prompt_template}」（有配置时）
5. 前端：财报页查询卡加「分析策略」按钮（financial:run 可见）→ 抽屉 textarea（maxlength 2000）+ 保存/清空；i18n 中英文
